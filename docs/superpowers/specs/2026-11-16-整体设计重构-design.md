# 《麦溪镇》整体设计重构方案

> 日期：2026-11-16
> 状态：设计基线已批准；2026-11-16 增补（主线、资源采集、建造、钓鱼与体验优先）已采用
> 适用范围：世界、人物、美术、玩法、UI、内容结构与实施顺序
> 替代关系：取代“75% 种田 / 5% 旅行青蛙 / 20% 古代戏剧本”的旧设计口径；现有代码、存档与数据作为迁移基础保留

---

## 1. 意图与原因

当前版本已经拥有 14 张地图、11 名 NPC、种田、畜牧、采矿、制造、任务、节日、信件与戏剧等大量内容，但整体体验没有形成统一作品。主要问题不是内容数量不足，而是：

- 西式小镇、中文姓名、古代王国戏剧、欧美绘本主菜单与动漫头像同时存在，世界观缺少统一口径。
- 系统数量多，但玩家每天真正感到有趣的动作少，许多内容以菜单和数值形式出现。
- 地图面积大而互动密度低，玩家大部分时间在走路，而不是发现地点和人物。
- 角色、建筑和地标缺少轮廓识别，离开文字标签后难以判断功能与性格。
- 主菜单、立绘和运行时画面使用不同的美术语言，首屏吸引力与实际游玩品质不一致。
- 信件和戏台原本具备差异化潜力，却被做成与农场、人物关系割裂的附加模块。

本方案希望保留《星露谷物语》最重要的体验原则：清楚的一天节奏、低理解成本的操作、可记忆的居民、密集的小镇空间、可见的长期成长。但不复制其像素美术、角色模板、地图布局或具体玩法。

最终作品应成为：

> 一款以“种田、邮路、戏台”为核心的纸上绘本式小镇生活 RPG。

玩家体验一句话：

> 白天把荒地种成家，傍晚沿邮路认识镇民，夜晚把他们的故事送上月桂戏台。

---

## 2. 目标

### 2.1 体验目标

- **温暖**：农场、屋舍、灯光、食物与人物互动让玩家感到归属。
- **清楚**：玩家不需要阅读长说明，就能理解工具、目标、地点和人物关系。
- **有生活**：NPC 有固定作息与可见的日常，世界不围绕玩家静止。
- **有手作感**：角色、建筑、地形、UI 统一呈现纸张、水粉与墨线的触感。
- **有秘密**：信件、旧戏页、镇史和人物关系逐步揭示小镇过去。
- **有表达**：玩家可以决定农场样貌、人物关系、戏剧选角与公演结局。

### 2.2 产品目标

- 保留 Godot 4.3、数据驱动地图、存档迁移、日程、天气、季节和手柄支持。
- 交付一条可完整游玩的春季垂直切片，再扩大内容，而不是继续横向铺系统。
- 让主菜单、角色、建筑、地图、UI、音效在同一个视觉与叙事口径下工作。
- 保留 macOS 与 Windows 导出能力，不引入联网、账号或第三方运行时依赖。

### 2.3 非目标

- 不复刻《星露谷物语》的像素画、角色比例、地图结构或具体系统组合。
- 不追求 38 名 NPC、数百件物品或无限生成内容。
- 不在首版加入联机、婚姻全流程、多人农场或大型战斗系统。
- 不把 AI 概念图直接作为最终运行时美术风格来源。
- 不为了“内容更多”保留质量不足、与世界无关或只存在于菜单中的系统。

### 2.4 反目标

- **系统越多越像生活游戏**：错误。生活感来自可理解、可重复、有反馈的日常动作。
- **地图越大越像完整世界**：错误。密度、地标和路线记忆比面积重要。
- **AI 图好看就能代表游戏品质**：错误。运行时角色、建筑与 UI 必须使用统一风格。
- **有戏剧模块就有独特玩法**：错误。戏剧必须参与农场、社交和信件循环。

## 3. 方案选择

### 方案 A：世界、人物与视觉整体重构，保留数据与存档骨架（采用）

以“纸上剧场”为统一视觉语言，把信件和月桂戏台提升为独立叙事支柱，先做春季垂直切片，再迁移现有内容。

**优点**：能同时解决世界观、视觉、玩法密度与内容割裂问题；现有数据、日程、天气、存档和地图框架可继续使用。
**代价**：角色、建筑、地图、UI、文本和部分玩法需要系统性返工，不能靠局部美化完成。

### 方案 B：只替换美术，保留当前玩法与内容结构（不采用）

**优点**：短期成本低，可快速改善截图。
**缺点**：75/5/20 的玩法重心、菜单式系统、大地图低密度和古代王国戏剧仍然割裂，无法解决核心体验问题。

### 方案 C：全面像素化，直接靠拢星露谷（不采用）

**优点**：类型认知最快，玩家容易理解。
**缺点**：容易变成外观模仿，浪费现有 AI 绘本资产与戏台、邮路题材；也会让作品失去自己的识别度。

**结论**：采用方案 A。学习《星露谷物语》的节奏和可读性，但使用本项目自己的视觉、人物和叙事机制。

## 4. 设计基线

### 4.1 世界口径

- 沿用虚构小镇 **麦溪镇 / Meadowbrook**。
- 世界采用架空西式河谷田园设定。
- 建筑、服饰、节日、戏剧与地名保持欧美田园幻想风格。
- 界面、对话、信件和任务使用中文。
- NPC 使用西方名字的中文化显示，不再混用中文姓名与西式小镇。
- 游戏内部 ID 尽量保持不变，显示名通过本地化字段替换，避免破坏存档与引用。

如果未来必须保留中文姓名，则世界、建筑、服饰和节日也必须整体改为架空东方河谷。不接受继续维持“西式建筑 + 中文姓名 + 古代王国剧本”的混用状态。

### 4.2 视觉基线

采用 **纸上剧场 / Paper Theatre**：

- 角色像纸偶，动作清楚、轮廓鲜明。
- 建筑像立体绘本布景，功能通过屋顶、门窗、招牌和道具表达。
- 地形带有轻微纸张纹理、水粉笔触和手绘边缘。
- 阴影柔和，光照温暖，避免当前过饱和、平涂和硬色块观感。
- UI 使用米白纸张、深棕墨字、印章色和手写批注感，不使用大面积黑色半透明横条。

### 4.3 玩法基线

| 支柱 | 占比 | 玩家行为 |
|---|---:|---|
| 农场与日常生活 | 50% | 种田、畜牧、采集、烹饪、扩建、季节变化 |
| 小镇社会与人物 | 30% | 日程、对话、送礼、委托、商店、节日、关系事件 |
| 信件与月桂戏台 | 20% | 送信、回信、镇史碎片、选角、排练、公演与结局 |

比例代表优先级，不是强制计时。季节活动贯穿三条支柱，不单独形成第四套系统。

### 4.4 交付基线

先完成春季垂直切片，再迁移全量内容。垂直切片必须证明：

- 视觉统一。
- 一天循环成立。
- 玩家愿意继续第二天。
- 信件与戏台已经进入主循环。
- 现有技术骨架没有被推翻。

本次实施计划只覆盖阶段 0–2。阶段 3–4 的完整四季制作范围，在垂直切片通过后重新估算并另立计划。

### 4.5 主角设定

采用主角为 **在外多年后回到麦溪镇的本地人**，而不是完全陌生的外来继承者：

- 主角童年每年夏天在麦溪镇度过，熟悉农场、邮局和旧戏台。
- 外祖父同时照料农场并参与过月桂戏台，主角因此既继承农场，也继承了未寄出的信和未完成的戏页。
- 十几年前戏台停演后，主角离开小镇；成年后因外祖父去世返回。
- 这条背景让种田、送信和戏台三条线都属于主角的私人记忆，而不是三份互不相关的工作。
- 主角姓名与外观由玩家自定义，主线对白使用中性称谓。

## 5. 视觉设计规范

### 5.1 镜头与基准

- 视角：3/4 俯视。
- 基准分辨率：1920×1080。
- 世界网格：64×64。
- 角色基础画布：96×144；在默认镜头下屏幕高度目标为 130–150 像素。
- 相机跟随主角，带平滑和地图边界钳制。
- 室内使用更近镜头或更紧凑空间，强调人物和家具。

### 5.2 角色语言

- 比例以 3.5 头身为基准，保留可爱感但避免完全幼儿化。
- 所有角色共享同一套骨架比例、着色层级和描边规则。
- 每个角色必须具备“主色 + 轮廓 + 随身道具”三个识别点。
- 核心 NPC 的道具应在世界动画中持续出现，而不是只存在头像里。
- 行走为 4 方向、8 帧；工具动作至少包含使用、完成和失败反馈。
- 对话头像使用同一角色设计，不另起动漫或写实风格。

暂定角色功能方向：

| 角色类型 | 功能 | 视觉识别 |
|---|---|---|
| 旅店老板 | 吃饭、打听消息、社交中心 | 围裙、托盘、暖色披肩 |
| 邮差/邮局长 | 信件、投递、镇外联系人 | 长外套、邮包、帽檐 |
| 木匠 | 农场扩建、舞台维修、制造 | 围裙、卷尺、宽肩 |
| 医生 | 恢复状态、人物事件 | 圆眼镜、药箱、浅色长外套 |
| 剧场导演 | 选角、排练、公演 | 长围巾、剧本夹、夸张手势 |
| 牧场主 | 牲畜、饲料、牧场支线 | 草帽、靴子、粗手套 |
| 杂货商 | 种子、工具、日常买卖 | 袖套、账本、蔬果箱 |
| 铁匠 | 工具升级、金属制品 | 皮围裙、锤子、炉火色 |
| 渔夫 | 鱼饵、鱼类、河湾消息 | 防水帽、鱼篓、绳索 |
| 史馆管理员 | 镇史、藏品、戏页归档 | 旧西装、放大镜、档案盒 |
| 行商 | 稀有商品、外地消息 | 大背包、地图、旅行斗篷 |

显示名在单独命名批次确定；在未锁定前继续使用现有内部 ID，避免代码与存档迁移风险。

### 5.3 建筑语言

- 建筑由“墙体、屋顶、身份部件、环境道具”四层组成。
- 遮住名称后，玩家仍应能识别建筑功能。
- 每栋建筑至少拥有一个动画细节：烟、灯、旗、晾衣、风车、蒸汽、开门或招牌摆动。
- 建筑占地、门框和碰撞必须优先服从可走性与入口辨识。

功能轮廓规范：

- 农舍：坡屋顶、烟囱、门廊、花箱。
- 谷仓：高门洞、蜜色木板、干草堆。
- 邮局：钟楼或鸽舍、蓝绿色门、信箱。
- 旅店：外挑招牌、暖窗、桌椅。
- 诊所：浅墙、十字窗、长椅、药草。
- 木工坊：木料、锯架、半成品。
- 剧场：舞台高台、幕布、灯架、海报墙。
- 杂货店：遮阳棚、蔬果箱、价目板。
- 牧场：围栏、饲料槽、风车、畜棚。
- 史馆：旧钟、展柜、石阶、档案箱。

### 5.4 UI 语言

- HUD 只保留日期、天气、金币、体力、当前地点和工具栏。
- 顶部信息改为轻量纸质卡片，不使用整条黑色遮罩。
- 工具栏固定在底部，显示手持工具和数量。
- 交互提示贴近目标显示，使用文字、图标和墨线，不使用黑色底框。
- 对话、商店、任务、信件和戏页使用同一套纸张卡片组件。
- 重要选项使用印章色按钮，不使用通用渐变按钮。
- 所有界面必须支持键鼠和手柄焦点导航。

### 5.5 色彩与光照

基础色板建议：

- 纸白：`#F4E8CF`
- 墨褐：`#3B2A20`
- 鼠尾草绿：`#7F9C6D`
- 草地黄绿：`#A8C46F`
- 陶土红：`#C46F4A`
- 蜂蜜黄：`#D9A441`
- 河水青：`#6FA7A5`
- 暮色蓝：`#6B789E`

四季在基础色板上调整，而不是整套换色：春季嫩绿与浅黄，夏季深绿与高光，秋季陶土与金色，冬季灰蓝、雪白与暖窗。

### 5.6 美术生产约束

- AI 图只用于概念、构图、立绘草案和材质参考，不直接定义运行时随机风格。
- 运行时角色、建筑和 UI 必须经过统一调色、描边、阴影与纸张纹理处理。
- 每张新增地图必须通过截图检查：遮住 UI 后仍能识别地点和主要功能。
- 每名核心角色的世界形象与头像必须并排验收，不能出现两套设计。

## 6. 世界与地图

### 6.1 世界结构

保留现有 14 个地点，但重新组织为五个空间层级：

| 层级 | 地点 | 主要作用 |
|---|---|---|
| 家 | 农场、农舍、谷仓 | 种田、扩建、睡觉、烹饪、畜牧 |
| 镇 | 镇中心、杂货店、邮局、旅店、诊所、木工坊 | 社交、买卖、委托、服务、日程交汇 |
| 水岸 | 河湾、柳溪林 | 采集、钓鱼、散步、隐藏信件与戏页 |
| 北侧 | 牧场、矿洞入口 | 畜牧、支线探索、稀有材料 |
| 文化区 | 月桂剧场、镇史馆 | 主线戏剧、镇史、收藏与公演 |

### 6.2 密度规则

- 玩家连续行走 6–10 秒必须遇到一个视觉地标、可互动对象或 NPC 路线。
- 每张地图至少有一个主地标、一个生活细节、一个与人物或故事相关的互动。
- 农场与镇中心开放地图缩小 20%–30%，减少无意义路程。
- 镇中心采用短回路和支巷，不使用一条超长主街。
- 室内地图保持紧凑，入口、服务对象和离开路径必须一眼可见。

### 6.3 路线与可读性

- 主路使用材质、边缘和道具共同区分，不仅依靠颜色。
- 门口设置门灯、门垫、屋檐或招牌，不靠碰撞体提示入口。
- 农场南门、商店街、剧场门口和河湾桥是四个主要视觉锚点。
- 地图边界使用栅栏、河岸、树线和建筑自然封闭。

## 7. 核心循环

### 7.1 每日循环

```text
起床
→ 查看天气与信箱
→ 照料作物和动物
→ 去镇上卖货、接委托、与镇民交谈
→ 送信 / 收集戏页 / 排练
→ 傍晚回家做饭或参加活动
→ 睡觉，进入次日
```

单日现实时间目标为 **25 分钟**（1.25 秒/游戏分钟，06:00 到次日 02:00 共 1500 秒）。时间必须让玩家做出选择，而不是因为走路而被迫放弃活动。

### 7.2 每周循环

- 集市日刷新稀有商品和人物委托。
- 邮局投递批次刷新。
- 戏台排练目标更新。
- 至少一次人物日程重叠，使玩家能观察到镇民之间的关系。

### 7.3 季节循环

- 每季 28 天。
- 每季包含作物窗口、采集变化、一个节日和一段月桂戏推进。
- 冬季降低农事强度，增加烹饪、关系、镇史和排练内容。

### 7.4 长期循环

- 修复农场：住房、谷仓、温室、围栏、道路和生活设施。
- 修复月桂戏台：清理、选角、排练、公演、镇史归档。
- 建立关系：从陌生、熟悉、信任到愿意分享秘密。
- 建立个人表达：农场布局、房屋装饰、戏剧选角和结局选择。

## 8. 农场与生活玩法

### 8.1 工具与操作

取消将翻土、浇水、播种、收获分别绑定不同记忆键的做法。采用快捷栏与上下文工具：

- 快捷栏选择锄头、水壶、种子、收获工具、鱼竿和其他道具。
- 交互键使用当前工具，目标高亮和动作预览必须清楚。
- 手柄支持快捷栏切换、确认、取消和工具使用。
- 基础操作目标：新玩家无需说明书即可完成第一天。

### 8.2 种田

- 保留 9 种作物、9 块初始农田和最多 24 块的扩建规模。
- 作物生长重点表达每日变化：湿润土壤、叶色、株高、花期与成熟提示。
- 浇水、翻土、播种、收获都要有地面痕迹、粒子、音效和短动画。
- 保留季节、天气和霜冻规则，但减少长时间等待和不可解释失败。
- 第一批作物必须在 4–6 个游戏日内提供完整正反馈。

### 8.3 畜牧与生活系统

- 畜牧保持 3 种动物、喂食、抚摸、产出和天气影响。
- 烹饪承接农场产出、恢复体力和送礼。
- 采集与钓鱼服务于烹饪、委托、人物礼物和戏台道具。
- 制造系统只保留与农场扩建、工具升级、戏台维修相关的内容。
- 矿洞改为可选采集与短解谜，不作为主线战斗系统。
- 镇史馆、公共工程和稀有收藏作为中期支线，不抢占首小时体验。

## 9. 人物与社会玩法

### 9.1 人物分层

11 名 NPC 分为：

- **6 名核心人物**：完整欲望、恐惧、秘密、日程、2–3 段高质量事件，参与戏台主线。
- **5 名功能人物**：承担商店、铁匠、渔夫、史馆、行商功能，同时拥有一段小故事和可见生活。

功能人物不为凑数写入与核心人物等量的事件。现有 33 段事件在迁移时重写和压缩为约 18–22 段高质量内容。

### 9.2 日程与相遇

- 每名 NPC 有家、工作地、休息地和季节变化。
- 至少一名核心人物在雨天、傍晚或节日改变行程。
- 玩家通过“在正确时间出现在正确地点”发现人物，而不是只在面板中遇到。
- NPC 之间的相处也要可见：同桌吃饭、门口聊天、剧场排练争执。

### 9.3 关系与事件

- 关系通过对话、礼物、委托、节日和戏剧选角共同增长。
- 好感事件使用短场景和明确选择，不依赖长文本说明。
- 每段核心事件至少改变一个状态：关系、物品、日程、戏页、店铺或镇史。
- 玩家选择必须有可感知后果，避免只改一行对白。

## 10. 信件与月桂戏台

### 10.1 信件玩法

- 玩家可以送信、取信、投递包裹和回复远方联系人。
- 每天最多一封主信件，避免形成强制打卡。
- 信件可包含地址模糊、旧名、错投、退回和私密内容。
- 玩家可以送达、退回、暂存或私下阅读，选择影响关系或解锁戏页。
- 信件是发现人物秘密和镇史的主要媒介，不是独立邮局小游戏。

垂直切片采用世界内投递，不做“在邮局菜单选择收件人”的替代方案：

- 玩家从邮局领取已分拣信件，同时携带最多 3 封。
- 每封信显示收件人、常去地点和投递窗口，玩家需要走到 NPC 或对应邮箱完成投递。
- NPC 按日程移动，错过窗口可以次日再送；垂直切片不设置永久失败。
- 允许玩家把信带回邮局退回，或私下阅读后再决定是否投递。
- 信件投递、退回和阅读状态必须写入存档。

### 10.2 月桂戏台

将“古代王国三幕戏”改为与麦溪镇历史直接相关的镇史剧《麦溪谣》：

- 故事围绕河湾、旧桥、火灾、第一场丰收和停演多年的戏台。
- 戏页通过农事、人物事件、信件、镇史和节日获得。
- 玩家决定角色由谁扮演，选角影响台词、排练冲突、关系变化和公演评价。
- 公演采用舞台演出段落，玩家决定台词、走位或关键舞台动作，而不是只点选项看文本。
- 公演结束后产出新的镇史页与人物关系结果，并改变下一季小镇状态。

舞台交互采用 **舞台指挥式选择**，首版不做自由走位：

- 公演由 3–5 个舞台节点组成，每个节点要求玩家选择台词、语气、灯光重点或让某名演员留在舞台中央。
- 选择在短时间窗口内完成，但不做高频反应判定；玩家可以暂停思考。
- 选角、关系状态和此前获得的戏页会改变可用选项及演出结果。
- 春季切片的第一幕必须包含“发现剧本 → 初次选角 → 3 个舞台节点的小型公演”，用于验证核心卖点，而不是只展示剧本文本。

三幕按季节推进：

1. 春季《河湾记得》——发现剧本、初次选角。
2. 夏季《桥上的黄昏》——关系冲突、排练与修改剧本。
3. 秋季《最后一盏灯》——公演、结局与镇史归档。
4. 冬季尾声——回信、镇史展和下一轮生活目标。

### 10.3 与农场和社交的互相供给

- 农场产出提供戏台道具、服装材料和节日食物。
- 人物事件提供戏页和选角动机。
- 信件连接远方联系人、镇外世界和旧日秘密。
- 公演结果反过来改变人物关系和下一季日程。

信件和戏台不能作为“另一个菜单系统”存在，必须在世界中有对应地点、人物和行动。

### 11.1 保留

- 存档、迁移、天气、季节、日程、对话与任务基础。
- 14 个地点和 11 名 NPC 的内部结构。
- 种田、畜牧、钓鱼、采集、烹饪、送礼、节日与音乐。

### 11.2 重构

- 角色比例、建筑轮廓、地图尺度、地形材质和镜头。
- NPC 显示名与世界口径。
- UI、字体、提示、工具栏和交互方式。
- 月桂戏台剧本、选角、排练和公演反馈。
- 14 张地图的动线、密度和视觉锚点。
- 主菜单、头像与运行时美术统一为纸上剧场风格。

- 不再新增大型系统。
- 不增加矿洞层数、藏品数量或任务条数。
- 不继续扩充服务面板。
- 不继续使用多套视觉语言。
- 不保留只增加数量、不改变体验的事件和物品。
- 不在垂直切片通过前扩大内容生产。

### 11.4 选择后果范围

垂直切片允许选择改变以下可玩状态：

- NPC 好感、信任或冲突标记。
- 解锁或关闭对白、人物事件和戏页。
- 当天或次日 NPC 日程中的一个可见变化。
- 商店一件货品的出现或价格小幅变化。
- 戏台角色分配、可用台词和公演结果。
- 一处地图装饰变化，例如海报、花箱、灯光或舞台道具。

垂直切片不做大型地图分支、整栋建筑重构、多结局世界状态或永久锁死人物事件。完整版最多扩展到商店货品池、节日内容和地图装饰，不为每个选择建立独立地图。

## 13. 验收标准

### 13.1 视觉验收

- 遮住 UI 后，截图仍能看出“纸上剧场”的统一风格。
- 遮住名字后，玩家可识别至少 8 种建筑功能。
- 遮住名字后，测试者可从轮廓和道具识别至少 5 名核心 NPC。
- 主菜单、头像、世界角色、建筑和 UI 并排时没有风格断裂。

### 13.2 操作验收

- 新玩家无需文字说明，在 3 分钟内完成翻土、播种和浇水。
- 新玩家在 5 分钟内能找到商店、NPC 与返回农场路线。
- 键鼠与手柄均可完成全部基础操作。
- 工具栏切换、使用、取消和失败反馈清楚。

### 13.3 内容验收

- 第一天结束后，玩家明确知道第二天要做什么。
- 前 30 分钟至少出现 3 个有意义选择。
- 单日 25 分钟内，玩家不会因路程放弃主要活动。
- 春季垂直切片中，信件和戏台至少各参与一次主循环。

### 13.4 技术验收

- 数据校验、AI 资产校验和全部 headless 测试通过。
- 目标设备 1080p 稳定运行。
- macOS 与 Windows 可导出并启动。
- 旧版本存档可加载，不出现关键状态丢失。

本设计采用：

- **纸上剧场**作为统一视觉语言。

- **50/30/20** 作为农场、社会与信件/戏台的玩法优先级。

## 17. 2026-11-16 增补基线：主线、资源、建造与钓鱼

> 本章为对前文的补充；若与前文冲突，以本章为准。
> 状态：已采用；按“体验优先、内容扩展随后”的阶段顺序进入实施。

### 17.1 体验优先级

新增内容不得打乱以下顺序：

1. **游戏性手感**：移动、交互判定、目标提示、采集与建造反馈、道路与碰撞。
2. **画面可读性**：纸上剧场统一风格、亮度、角色与建筑辨识度。
3. **交互密度**：每个屏幕内至少有可做的事、可看的地标或可遇见的人。
4. **内容铺量**：主线、资源、鱼类与季节内容在基础体验稳定后扩展。

“先打磨游戏性”不是只调数值，而是要求资源采集、建造、钓鱼和主线都能在第一个春季切片里形成清楚、可重复、有反馈的循环。

### 17.2 主线：《灯火归溪》

新增一条贯穿全局的主线 **《灯火归溪》**。主线不是独立菜单，而是把农场、人物、信件、戏台、采集、钓鱼与建造串成同一条回流：

```text
回到农场 → 恢复生活 → 送出旧信 → 发现旧戏 → 修复戏台 → 春夜开台 → 四季巡回
```

主线共 6 章。阶段 0–2 只实现第 1–5 章的前置与小目标，第 6 章留到完整四季计划。

| 章 | 名称 | 主要目标 | 资源帮助 |
|---:|---|---|---|
| 1 | 回到麦溪镇 | 播种 3 块地、与 3 名镇民交谈、睡过第一夜 | 8 包春季种子、5 份软木、3 份芦苇纤维 |
| 2 | 没有寄出的信 | 完成 2 次世界投递、阅读 1 封旧信 | 4 块铜矿、2 块煤、2 组鱼饵、斧头二级图纸 |
| 3 | 旧桥的戏页 | 发现剧本、完成初次选角、完成第一幕公演 | 6 份硬木、4 块石料、1 套舞台修补件、镰刀二级图纸 |
| 4 | 海潮带来的消息 | 钓到 3 种淡水鱼、1 种海鱼、放置 1 件建造物 | 1 张鱼竿升级图纸、3 个稀有鱼饵、4 份硬木、采集篮二级图纸 |
| 5 | 春夜开台 | 完成春季 14 日切片、第一幕归档、春播集市参与 | 1 台简易喷灌器、2 株果树苗、6 袋肥料、1 组路面材料 |
| 6 | 四季之后 | 完成三幕公演与四季巡回（完整版） | 戏台修复、稀有种子、镇史展与长期装饰 |

规则：

- 主线奖励不直接塞进背包，而是在章节完成后的次日送到农场信箱；玩家互动领取，领取一次后不可重复。
- 奖励必须包含“资源帮助”，不能只给金币。种子、木材、矿石、纤维、鱼饵、图纸、建造件和工具升级材料都属于奖励范围。
- 主线目标进度由真实系统事件推进，不允许使用独立计数器伪造。农场播种、NPC 交谈、信件投递、戏剧节点、钓鱼、放置建造物都要从所属系统写入主线进度。
- 当前章节目标在 HUD 的纸张主线卡中显示；完整章节列表通过暂停菜单或任务面板查看。
- 主线不锁死支线、商店、节日或关系事件。未完成主线时，玩家仍可自由生活。
- 第 1–5 章的所有资源奖励总额必须足够让玩家跨过一个工具或建造门槛，但不足以跳过整个采集循环。

### 17.3 资源分类与采集工具

资源分为五类，分别使用不同工具：

| 资源类 | 工具 ID | 典型节点 | 一级可采 | 二级解锁 | 三级解锁 |
|---|---|---|---|---|---|
| 木材 | `axe` | 倒木、软木树、硬木树、老树桩 | 软木、树枝、树脂 | 硬木、树皮纤维 | 古木、稀有树脂 |
| 矿石 | `pickaxe` | 石堆、铜脉、铁矿、深层晶脉 | 石料、煤、铜矿 | 铁矿 | 金矿、琥珀、晶簇 |
| 植物 | `sickle` | 芦苇、野草、草药丛、发光草 | 芦苇纤维、野草、普通草药 | 香草、染料花 | 月辉草、稀有菌丝 |
| 瓜果 | `harvest_basket` | 野莓丛、苹果树、葡萄架、南瓜地 | 野莓、苹果 | 葡萄、梨、南瓜 | 金苹果、蜜瓜 |
| 鱼类 | `fishing_rod` | 河湾、海潮湾 | 常见淡水鱼 | 稀有淡水鱼、常见海鱼 | 稀有海鱼、传说鱼 |

采集规则：

- 每个节点拥有稳定 `node_id`，按绝对游戏日记录上次采集时间；同一天读档不会刷出第二份。
- 节点有 `respawn_days`，到期自动恢复，不需要玩家重新进图。
- 工具等级不足时，节点保留并显示“需要二级斧头”等明确提示，不消耗体力。
- 错误工具不会损坏节点；给出正确工具提示。
- 采集消耗体力和少量游戏时间，不引入工具耐久或工具损坏系统。
- 每次采集写入资源、任务、主线和技能经验。

### 17.4 工具升级扩展

在现有 `tool_upgrades.json` 上扩展，不新建第二套等级：

- `hoe`、`water`、`pickaxe` 保留现有 1–3 级。
- 新增 `axe`、`sickle`、`harvest_basket`、`fishing_rod` 的 1–3 级。
- 每级工具必须同时提供“数值增强”和“资源门槛解锁”，不能只减少体力。
- 升级材料来自采集、矿石冶炼和主线奖励，形成“采集 → 制造 → 升级 → 采集更深资源”的闭环。
- 工具升级仍在铁匠服务中完成；新增图纸由主线或人物事件解锁，不把所有升级直接开放。

### 17.5 道具建造与路面精度

新增 **农场建造**，首版只允许在 L01 农场范围内放置，不改变 NPC 寻路或镇中心布局。

首批可建造物：

| 建造物 | 占用 | 碰撞 | 作用 |
|---|---:|---|---|
| 木栅栏 | 1×1 格 | 有 | 划分农田与步道 |
| 石板路 | 1×1 格 | 无 | 精确拼接道路，略微提高行走速度 |
| 木储物箱 | 1×2 格 | 有 | 家庭储物扩展 |
| 简易喷灌器 | 1×1 格 | 有 | 每晨浇灌周围 3 块地 |
| 工作台 | 2×1 格 | 有 | 农场内制造入口 |
| 门灯 | 1×1 格 | 无 | 夜间行走照明与装饰 |
| 邮箱 | 1×1 格 | 有 | 接收主线奖励与信件 |

放置规则：

- 64×64 网格吸附，预览体必须显示绿色可放置、红色阻挡、黄色资源不足三种状态。
- 不允许与建筑、树木、水、门、NPC 固定路线、已有建造物重叠。
- 路面无碰撞，但必须与主路、门口和建造物入口精确对齐。
- 建造物写入存档；拆除后退回对应建造道具，不退回原材料。
- 首版不实现整栋房屋建造、墙体承重、屋顶或多人农场。

道路与网格精度：

- 主路宽度为 192 像素（3 格）或 256 像素（4 格），支路至少 128 像素（2 格）。
- 道路矩形边缘、门口、桥头、广场和建造格必须落在 64 像素网格上。
- 新增 `MapDatabase.road_audit(map)`，检查道路是否越界、宽度是否合规、是否穿过建筑落地碰撞、所有门是否能从道路网络到达。
- 路面渲染使用相同的 64 像素模块，不靠手绘长条贴图掩盖接缝。
- 碰撞体与视觉路面分离：视觉可以柔和，通行边界必须明确。

### 17.6 钓鱼扩展

钓鱼从“单水位随机鱼”升级为“水域 × 天气 × 季节 × 鱼竿等级 × 稀有度”的筛选系统。

- 水域：`freshwater`（河湾、柳溪林水塘）、`saltwater`（新增 L15 海潮湾）。
- 天气：晴天、阴天、雨天分组；不同鱼种拥有 `weather` 列表。
- 季节：春、夏、秋、冬各有独立鱼池；部分鱼全年存在。
- 稀有度：`common`、`uncommon`、`rare`、`legendary`。
- 价值：稀有度越高，售价和料理价值越高；传说鱼不进入普通商店低价收购池。
- 鱼竿等级控制可钓稀有度；鱼饵提高稀有鱼权重，不保证结果。
- 新增 L15 海潮湾：从 L09 河湾南侧进入，单屏海岸地图，拥有独立配乐 `coast` 与海水钓点。
- 钓鱼 UI 显示水域、天气、季节和可钓等级，不提前显示未钓到的鱼名。

### 17.7 时间流速

单日现实时长调整为 **25 分钟**：

- 06:00 到次日 02:00 共 1200 游戏分钟。
- `REAL_SECONDS_PER_GAME_MINUTE = 1.25`。
- 单日完整时长 1500 现实秒。
- 旧存档时钟分钟数不变，只改变现实秒换算。

### 17.8 新增验收

- 主线第 1 章可在前 2 个游戏日内完成，奖励在次日送达并只能领取一次。
- 五类资源各至少 3 个节点；一级工具只能采一级资源，二级和三级工具分别解锁对应节点。
- 同一节点重复采集在冷却内失败；跨天和读档后冷却正确。
- 至少 3 种建造物可放置、拆除、存档并正确参与碰撞；路面可以无缝拼接。
- 淡水与海水鱼池不混池；晴天、雨天、四季和鱼竿等级筛选正确；稀有鱼价值高于普通鱼。
- L15 可从 L09 进入并返回，门、钓点、音乐与碰撞通过场景测试。
- 单日现实时长精确为 25 分钟。
